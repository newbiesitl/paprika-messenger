# Paprika Messenger company

An open-source software studio organized as a lean team. The approved roster is Coordinator, Architect, Developer, QA and Release Engineer.

Start with [company.json](company.json), the [ownership map](ownership.json) and the role contracts under [roles/](roles/). The [constitution](CONSTITUTION.md) describes shared boundaries; [WORK.md](WORK.md) and [ADOPTION.md](ADOPTION.md) cover work records and definition changes.

The catalog selection is retained in `catalog-selection.json`. The separately retained `refined-blueprint.json` contains the contracts tailored to this repository. Catalog re-export produces starter prose and does not preserve those refinements.

Definitions are a bootstrap candidate until reviewed and adopted. Live role-chat bindings and onboarding receipts are kept privately under Git state. The selected engineering-core pack requires a separate project-local installation; its references do not prove local availability. Model settings remain the host defaults unless the owner selects an override.

The owner selected an existing dedicated company communication board. Its verified service and board binding is private, outside public source, under the Git common directory's `paprika-inc/company-board-binding.json`. Use that binding explicitly for later authorized company communication.

Initialization does not grant standing peer messaging, merge, publication, account installation or deployment authority. Native role-chat creation and read/report onboarding use a separately requested bootstrap step.
